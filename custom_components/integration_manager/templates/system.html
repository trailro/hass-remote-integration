Every version change takes a backup of the current configuration first, then restarts the process. A version that is not installed yet goes into a new venv on the volume (a few minutes, this page shows the progress); the previous venv is kept for rollback, and the container falls back to it if the install or the boot fails. The integration's requirements are reinstalled into the new venv automatically. Home Assistant migrates its configuration forward only, so a downgrade lets you restore .storage from a backup made on that version or an older one, or start clean and rebuild the integration's configuration. The integration version and the manager state stay as they are.

Backup & restore

A backup is a zip of .storage (registries, config entries), custom_components, the manager's state/settings/versions/patches and the YAML files. One is taken automatically before every start that changes something (pre-start-…, pre-update-…), before a restore (pre-restore) and optionally daily. Restore is applied by the entrypoint at the next restart, for the parts you choose.
