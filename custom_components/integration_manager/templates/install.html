Install

Getting code into the version store: a release of a registry integration, any GitHub ref with a chosen Home Assistant version (checked first), or a directory you are working on. Nothing runs until you start it from the Overview or the Integration page.

Quick install from the registry

One integration per container: choosing a different one than the installed … replaces it (its config entries, patches, YAML and retained MQTT documents are removed after a backup pre-replace-…; restoring that backup brings it back). Another integration alongside = another container (HRI_NAME, HRI_PORT).

Environment builder

Pick an integration, a version and a Home Assistant version. Check unpacks the release, resolves its requirements with pip in dry-run mode, evaluates the patches, the dependencies and the minimum HA version, and validates the HA release, without touching the running environment. Prepare installs the version into the store and pins the HA version; Prepare & start also starts it (a backup is taken first when something is running). A different HA version is installed by the entrypoint at the restart that follows, and the integration's requirements are reinstalled into that venv.

Dev mode · install from a directory

A directory bind-mounted into the container (docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d mounts ./dev-src read-only at /dev-src; the directory itself, <dir>/<domain>/ or <dir>/custom_components/<domain>/ must hold a manifest.json). It lands in the version store as local and is started like any version; "Reinstall + restart" refreshes the running copy from the directory. HRI_DEBUGPY=5678 in the environment makes the process listen for a debugger on that port (VS Code: attach to localhost:5678). Exceptions: the Logs page.
